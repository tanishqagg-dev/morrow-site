# Morrow's exact Codex-based customer flow

Corrected 24 September 2026 after inspecting the actual runtime. This is the authoritative login, voice, and payment flow for the proposed consumer release. It replaces the corresponding sections of `report.md` wherever they differ.

## What Morrow actually is

Morrow is a friendlier desktop interface around a bundled, isolated **Codex app-server**. The customer's ChatGPT account authorizes Codex. In the current code, `begin_chatgpt_login` calls `account/login/start` with `type: chatgpt`, opens the official OpenAI URL in the default browser, and checks the resulting account with `account/read`. Pressing Speak starts `thread/realtime/start` with WebRTC, `outputModality: audio`, and the Codex Live model `gpt-live-1-codex`. Codex handles the voice conversation and subsequent agent work. There is no separate Morrow model, OpenAI API key, or speech-provider selection in this intended path. See [native login and voice code](../../../src-tauri/src/lib.rs).

The OpenAI subscription and the Morrow subscription are distinct:

| Payment | Pays for | Account | Where managed |
| --- | --- | --- | --- |
| ChatGPT/Codex plan | The customer's eligible Codex use and associated OpenAI limits | ChatGPT/OpenAI | OpenAI |
| Morrow plan | The Morrow app experience, licensing, updates, and support | Morrow | Morrow website |

[OpenAI's current guide](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) says Codex is included across ChatGPT plans, including Free and Go, with limits that vary. Do not say every customer must buy Plus or Pro unless Morrow intentionally restricts supported accounts after testing. Do not say a Morrow payment increases OpenAI usage limits. The Codex voice capability available to Morrow's bundled runtime must be tested for each supported plan and workspace.

## Recommended journey

1. **Website.** The main button is "Download Morrow" once a customer-ready build exists. Beside it: "Uses your ChatGPT account for Codex. Morrow is a separate subscription after your first conversation." The site can state an exact trial length only after it is implemented.
2. **Install and open.** The app opens to a short welcome with one primary action: "Connect ChatGPT". It silently obtains a limited, server-signed Morrow trial entitlement for this installation. This matters because today's `begin_chatgpt_login` calls `licensing::require_active()` first. Until the trial entitlement or an equivalent prepayment access state exists, the proposed first run cannot work.
3. **Connect Codex.** Morrow invokes the existing Codex `account/login/start` flow. The customer signs in on OpenAI's real browser page and returns. Morrow uses `account/read` to confirm the account. It shows "Connected to ChatGPT" plus the account identity and a clear retry if the wrong account was used. The customer never pastes an API key or a ChatGPT password into Morrow.
4. **First voice conversation.** The app says "Press Speak and tell Morrow what you need." On first press, macOS asks for microphone access. Morrow starts its existing Codex realtime WebRTC session; the person speaks, hears Morrow, sees a live transcript and response, and can interrupt. Text input is always available. This is a genuine Codex session, not a scripted demo. Keep the first example simple, such as "Help me understand this letter" or "Help me plan my day." If a task needs files or another app, request that access when needed.
5. **Morrow paywall.** After the promised trial allowance, the app says "Keep using Morrow" and shows the Morrow price, renewal, tax, cancellation, and separate ChatGPT requirement. The app opens a Morrow-owned HTTPS checkout page **in the default browser**. The browser page carries a short-lived, single-use pairing request generated by the app; the customer signs into a Morrow account with Clerk and pays through Razorpay.
6. **Verify and return.** Razorpay's client callback only says checkout returned. The backend verifies the signed event and active paid term, associates the Morrow account with the pending installation, and issues a signed entitlement to the app. The site shows "Open Morrow" through an installed-app link; the app also polls for the one-time pairing result so the user can simply switch back. Morrow verifies its entitlement and opens the same conversation. No activation code to copy.
7. **Everyday use.** On later launches Morrow checks its license and the saved Codex account separately. If both are valid, Home opens straight to Speak. Settings shows two distinct rows: "Morrow plan" and "ChatGPT connection." Billing, invoices, cancellation, and plan changes open the web account page. ChatGPT reconnect opens the official OpenAI browser login.

```text
Website → Download app → Connect ChatGPT (official browser)
        → Press Speak → real Codex voice conversation
        → trial ends → Morrow browser sign-in + Razorpay checkout
        → verified paid entitlement returns to same app conversation
```

**If Morrow will not offer any trial**, move Morrow checkout before step 3. This is simpler to license, but customers pay before confirming that their ChatGPT account and microphone work. I recommend the limited real conversation because Morrow's value is felt through speaking, and the trial's AI use draws on the customer's own eligible Codex allowance. Set the trial limit only after the billing and authorization rules are decided.

## Why checkout belongs in the browser

The repo already has [Clerk sign-in, a Razorpay checkout, verified callbacks, and a billing account page](../../../website/components/BillingPortal.tsx). Reuse that web path. It keeps payment authentication and payment-method handling in the customer's familiar browser and lets the app stay focused on speaking. The app should open the page and receive the result automatically. Do not embed a card form in the Tauri window and do not make the customer manually transfer an activation code. If future distribution uses an app store, review its payment rules for that channel before shipping.

## What must change in this repository

1. **Trial access before Codex login.** Current native login requires an active Morrow license. Add a limited trial entitlement or an explicit safe prepayment state. Keep normal agent permissions and trial limits enforced by the native host and server; hiding the paywall in React is not an entitlement system.
2. **Replace code claim with account-to-device pairing.** Today's [billing flow](../../../docs/MORROW_BILLING.md) issues one-time codes after `subscription.charged`. Add a one-time pairing request and signed entitlement claim tied to the Clerk customer and current installation. Keep manual codes only as support/pilot fallback.
3. **Return from checkout.** Register a verified installed-app URL scheme or universal link and implement a polling fallback. The existing `morrow://pair` references are for iPhone companion pairing, not a completed desktop payment return path.
4. **One customer plan.** Keep Business/operator tooling in the backend if needed, but remove team seats and company account creation from the first-time consumer checkout. The current published price rows are drafts; do not treat the ₹3,499 Personal preview as a validated launch price.
5. **Fix product language.** The main app first-run action should be "Connect ChatGPT", then "Speak". The site should say "Powered by your ChatGPT account's Codex access" and identify Morrow's separate fee. Remove "choose an AI provider," "API key," and separate speech-provider messaging from consumer flow.
6. **Verify the full path on a signed customer build.** Current Pilot inspection was interrupted by a Keychain activation error. Test install → trial entitlement → official Codex login → account read → realtime voice → browser checkout → signed charge webhook → automatic app unlock → renewal/cancel/restore.

## Failure and return states

- **ChatGPT account unavailable or limit reached:** preserve the conversation; show the OpenAI account/usage issue. Buying Morrow is not presented as the fix.
- **Microphone denied:** show macOS settings and allow typing. Morrow billing remains unchanged.
- **Browser checkout closed:** leave trial or expired state intact and keep local history readable.
- **Payment completed, webhook late:** show "Checking payment" and poll; do not grant access from the browser success callback alone.
- **App did not reopen:** user can return manually; the app polls the pending pairing request. "Restore purchase" re-links through Morrow web sign-in.
- **Morrow expires:** stop new paid sessions according to plan rules; keep existing local conversations and exports accessible.
- **ChatGPT signs out:** request official OpenAI login again without charging Morrow a second time.

## Release gate

The code demonstrates the intended integration, not permission to sell it. Confirm that the account-authenticated Codex app-server and realtime voice path may be distributed in a paid third-party Morrow app, and test entitlement and usage behavior on supported ChatGPT plans. [OpenAI's Sign in with ChatGPT](https://help.openai.com/en/articles/20001410-sign-in-with-chatgpt) is only an identity service and must not be confused with Codex inference authorization.
